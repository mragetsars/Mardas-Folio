# بازبینی جزئیات تعامل ادیتور

تاریخ: ۲۰۲۶-۱۰-۲۶. مبنا: تصاویر و تجربهٔ گزارش‌شدهٔ کاربر روی Trial، کد واقعی CodeMirror و برنامه، بستهٔ نصب‌شدهٔ Office Viewer 4.2.0 و [مستند قالب‌بندی جدول Obsidian](https://obsidian.md/help/advanced-syntax) و [چیدمان VS Code](https://code.visualstudio.com/docs/configure/custom-layout).

این دور بر انتخاب، جدول، تشخیص پنل‌ها و تغییر اندازه متمرکز است. Office Viewer از متغیر انتخاب مخصوص ادیتور استفاده می‌کند؛ کپی رنگ به‌تنهایی مشکل Folio را حل نمی‌کرد. در Folio، `::selection` بومی با `!important` هم‌زمان با مستطیل‌های انتخاب CodeMirror رنگ می‌گرفت. اصلاح، حفظ یک لایهٔ رسم مبتنی بر bidi و تعیین رنگ متمرکز/غیرفعال است.

| یافته | اصلاح و معیار پذیرش |
| --- | --- |
| رنگ انتخاب دوبار روی متن می‌افتاد | انتخاب بومی در ادیتور شفاف است؛ فقط لایهٔ رسم CodeMirror رنگ دارد. انتخاب فارسیِ شکسته‌شده در چند سطر با کلید واقعی آزمایش می‌شود. |
| خط فعال به رنگ انتخاب اضافه می‌شد | هنگام انتخاب بازه، زمینهٔ خط فعال حذف می‌شود؛ رنگ انتخاب متمرکز و غیرفعال مستقل است. |
| Preview و Inspector آیکون یکسان داشتند | Preview آیکون چشم و Inspector آیکون تنظیمات سند دارد؛ برچسب‌های قابل مشاهده و وضعیت باز/بستهٔ قابل دسترس اضافه شدند. |
| رنگ جداکننده، کل ناحیهٔ گرفتن ماوس را پر می‌کرد | ناحیهٔ گرفتن ۱۲px باقی می‌ماند؛ خط نمایان ۱px و هنگام تعامل حداکثر ۲px است. |

| بازخوانی متن جداشدهٔ جدول، پیشوند quote/list را اشتباه می‌گرفت | widget از همان درخت parser ادیتور استفاده می‌کند؛ جدول داخل نقل‌قول و offset سورس حفظ می‌شوند. |

| پیام تصویرهای مسدودشده و URLها به هم می‌چسبیدند | کارت کوچک و ترجمه‌شده در Write/Read/Preview؛ مسیر کامل در title و سورس باقی می‌ماند. سیاست بارگیری تصویر تغییر نمی‌کند. |
| برچسب‌های تازه می‌توانستند ابزارهای رایج را به More برانند | زیر عرض ۱۲۰۰px بوم، نوار قالب‌بندی ردیف مستقل می‌گیرد؛ معیار، عرض خود بوم است. |

| کلیک جدول پس از یک انتخاب قبلی می‌توانست بازهٔ مبهم بسازد | کلیک عادی، مکان‌نمای جمع‌شده در ابتدای همان سلول ایجاد می‌کند؛ تایپ و Undo با مقایسهٔ دقیق سورس آزموده می‌شوند. Shift-click بازه را به‌صورت صریح گسترش می‌دهد. |

کلیک جدول، Markdown واقعی را برای ویرایش آشکار می‌کند و خروج از آن دوباره جدول را رسم می‌کند. تغییر چیدمان و شکل انتخاب، سند را بازنویسی نمی‌کند. بلوک‌های تصویر اینترنتی، صرفاً توضیح خوانا می‌گیرند و درخواست شبکه ایجاد نمی‌کنند.

## شواهد پذیرش

- `scripts/audit_editor_interactions.py`: چهار ترکیب زبان/تم/عرض، CodeMirror و EngineService واقعی، فایل مصنوعی مستقل؛ قالب‌های تو‌در‌تو، ریاضی، جدول داخل quote، pipe، HTML بی‌اثر، انتخاب و Undo، آیکون‌ها، عنوان، placeholder و کشیدن/لغو/Escape/صفحه‌کلید.
- `build/interaction-details/acceptance/report.json`: نتیجهٔ آزمون جزئیات و تصاویر قبل از پایان سناریوها.
- `build/interaction-details/node.log`: ۳۱۵ تست JavaScript موفق.
- `build/interaction-details/python-desktop.log`: ۴۲ تست desktop موفق.
- `build/interaction-details/behavior/report.json`: چهار ترکیب زبان/تم، هرکدام ۲۱ بررسی موفق؛ پس از اصلاح نهایی popup و کلیک سلول دوباره اجرا شد.
- `build/interaction-details/responsive/report.json`: شانزده حالت موفق؛ دسترس‌پذیری ساختاری نیز موفق است. این بررسی، آزمون انسانی screen reader نیست.
- `build/interaction-details/native-final.json`: هفت بررسی بومی Windows روی ساخت نهایی `849d8df`؛ جدول، انتخاب واقعی، popup داخل ادیتور، کشیدن جداکننده از ۵۰۰ به ۵۳۲، مکان‌نمای سلول و تایپ/ذخیرهٔ دقیق، Undo و ذخیرهٔ بازگشت، Inspector مستقل و خروج پاک.
- `build/interaction-details/runtime-final.log`: تأیید موجودی ۷۰۰ فایل و رندر واقعی موتور پس از آزمون بومی موفق است. موتور از ساخت تأییدشدهٔ `df22541` استفاده می‌کند؛ ورودی‌های موتور و دارایی‌های آن با snapshot سازگارند.

کامیت‌های پیاده‌سازی: `3ef9e07`، `e7528c7` و `849d8df`. سندهای خصوصی کاربر ورودی آزمون نیستند؛ fixtureها در پوشه‌های موقت اختصاصی ساخته می‌شوند.
