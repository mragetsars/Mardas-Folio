# بازطراحی تجربهٔ ادیتور Markdown

تاریخ بررسی: ۲۰۲۶-۱۰-۰۹. مبنای بررسی رابط قبلی: `b49855d`، پیش از اجرای این بازطراحی.

در این مرحله مسئلهٔ اصلی تجربهٔ نوشتن و حرکت بین سندهاست. مرتب‌شدن رنگ‌ها، کنتراست و فاصله‌ها به‌تنهایی نمی‌تواند محیطی را که هنوز مانند فرم ساخت PDF سازمان یافته، به ادیتور Markdown تبدیل کند. درخواست کاربر مبنای این بازطراحی است: ساختار قبلی الزام طراحی نیست.

## روش بررسی و حد ادعا

مستندات رسمی فعلی Obsidian، VS Code و Typora بررسی شد؛ رفتار محصولات از این منابع استخراج شده است. ساختار HTML، ترجیحات، فرمان‌ها و جریان فعال‌کردن سند در سورس برنامه، همراه با تصویر واقعی `build/repo-audit/design-final/light-en-04-write.png` بررسی شد. این مرحله ادعای آزمون عملی نسخهٔ نصب‌شدهٔ محصولات دیگر یا پژوهش با کاربران واقعی ندارد. پیشنهادهای زیر تصمیم و استنباط طراحی برای این محصول‌اند؛ مشابه‌بودن یک الگو با محصول دیگر، اثبات مناسب‌بودن آن برای کاربران ما نیست.

## مدل پیشنهادی محیط

سه مسئولیت باید در محیط قابل تشخیص باشد: «کدام فایل؟» در ناوبر فایل، «چه می‌نویسم؟» در بوم مرکزی، و «در این سند چه ساختاری دارم؟» در ابزار سند. هدر بوم، هویت فایل و وضعیت ذخیره را نزدیک متن نگه می‌دارد. ابزار قالب‌بندی و درج، از یک کنترل روشن و فرمان‌های قابل جست‌وجو باز می‌شود؛ کاربر مبتدی مجبور به دانستن syntax نیست، و کاربر باتجربه نیز مجبور به دیدن همهٔ ابزارها نیست.

Write برای نوشتن روزمره با live preview است؛ Source برای کنترل مستقیم Markdown و YAML؛ Reading برای مرور بدون تغییر سند؛ Split برای مقایسهٔ سورس و نتیجه. Reading و Split باید نتیجهٔ موتور را از بوم نویسندگی و از ظاهر نهایی PDF قابل تشخیص نگه دارند. نمایش خطا یا بارگذاری جدید، دلیل جابه‌جایی فایل یا تغییر مکان caret نیست.

در نمایشگر کوچک، ابزارها به پنل موقت تبدیل شوند و متن عرض اصلی را داشته باشد. دکمهٔ بستن و بازگرداندن focus بخشی از همین جریان است. حالت تمرکز، یک اقدام مستقل با راه خروج واضح است؛ Typewriter انتخاب جدا و خاموش در شروع است.

## فهرست اولویت و معیار پذیرش

این فهرست معیار اجرای بازطراحی است؛ تیک‌نخوردن یک مورد یعنی هنوز برای آن شواهد پذیرش ثبت نشده است. شواهد باید نتیجهٔ مشاهدهٔ برنامهٔ ساخته‌شده باشند، نه صرف وجود selector در HTML.

### P0 — جریان اصلی نوشتن

- [x] **E01 — شروع ساده:** یک فایل `.md` یا یک سند خالی، بدون ساخت پروژه و بدون ورود به تنظیمات PDF، مستقیم به محیط ویرایش برسد؛ caret آمادهٔ نوشتن باشد.
- [x] **E02 — ناوبر فایل واقعی:** همهٔ اسناد باز مستقل از پروژه دیده شوند؛ انتخاب فایل، active و dirty را درست نشان دهد. دو فایل هم‌نام با مسیر تشخیص‌پذیر باشند.
- [x] **E03 — جدایی فایل و ابزار سند:** بازکردن outline/properties باعث بسته‌شدن Explorer نشود؛ هر ناحیه مستقل قابل پنهان‌کردن باشد.
- [x] **E04 — کاهش chrome:** ابزارهای مربوط به انتشار در جایگاه اصلی نوشتن غالب نباشند؛ toolbar قالب‌بندی قابل نمایش/پنهان‌شدن باشد و مخفی‌شدنش واقعاً فضا آزاد کند.
- [x] **E05 — هویت سند:** نزدیک بوم، نام/عنوان، مسیر و saved/unsaved دیده شود؛ مسیر طولانی از راه قابل دسترس کامل خوانده شود.
- [x] **E06 — چهار رفتار نمایش:** Write قابل ویرایش، Source سورس واقعی، Reading غیرقابل ویرایش و Split مقایسهٔ سند فعال باشد؛ نام‌ها و شرح کوتاه تفاوت را آشکار کنند.
- [x] **E07 — حفظ حالت سند:** جابه‌جایی تب یا حالت نمایش، Undo/Redo، متن، انتخاب و مکان پیمایش همان سند را حفظ کند؛ Undo سند A هیچ‌گاه سند B را تغییر ندهد.
- [x] **E08 — بازشدن ناهم‌زمان امن:** اگر آماده‌سازی تصویر یا فایل جدید طول بکشد، نوشتهٔ کاربر همچنان در سندی ثبت شود که روی صفحه می‌بیند؛ لغو یا رفتن به خانه انتخاب دیررس را خنثی کند.
- [x] **E09 — تمرکز واقعی:** ورود به Focus ابزارهای اضافه را از نمایش و focus خارج کند؛ خروج با کنترل قابل دیدن و Escape ممکن باشد و چیدمان قبل برگردد.
- [x] **E10 — حرکت سریع:** `Ctrl/Cmd+P` انتخاب سند/فایل و `Ctrl/Cmd+Shift+P` انتخاب فرمان باشد؛ فلش‌ها و Enter کار کنند، Escape ببندد و focus را برگرداند.

### P1 — کار با متن و سند بلند

- [x] **E11 — قالب‌بندی قابل کشف:** Bold، Italic، لینک، عنوان، فهرست و درج بلوک از کنترل مشخص و فرمان جست‌وجوشدنی در دسترس باشند؛ اجرا روی انتخاب فعلی باشد و undo یک اقدام قابل فهم باشد.
- [x] **E12 — outline کاربردی:** سطح عنوان‌ها روشن باشد؛ انتخاب عنوان به جای درست برود؛ افزودن/حذف عنوان فهرست را بدون تغییر focus ناخواسته تازه کند.
- [x] **E13 — خواندن پیوسته:** Reading همان سند فعال را نشان دهد؛ محتوای قدیمی سند قبلی در انتظار رندر به‌عنوان نتیجهٔ جدید نمایش داده نشود؛ حرکت outline با این نما نیز کار کند.
- [x] **E14 — جست‌وجوی متن:** Find/Replace در محل قابل پیش‌بینی باز شود؛ Enter/Shift+Enter نتیجهٔ بعد/قبل، Escape بستن، و شمار نتیجه قابل فهم باشد. در Reading، جایگزینی اجازهٔ تغییر پنهانی متن ندهد.
- [x] **E15 — ویژگی‌های نویسندگی:** عرض خواندن، نوع نمایش متن و Typewriter به‌صورت آگاهانه قابل انتخاب باشند؛ تغییر آن‌ها متن یا history را بازسازی نکند.
- [x] **E16 — مشخصات کم‌خطر:** properties به سند فعال تعلق داشته باشد؛ YAML ساختاریافته در فرم خراب نشود؛ درخواست اصلاح آن به Source مسیر روشن داشته باشد.
- [x] **E17 — انتشار از متن فعلی:** Export از سند فعلی و تغییرهای ذخیره‌نشده آگاه باشد؛ ورود و خروج از تنظیمات خروجی جای نوشتن را حفظ کند.

### P1 — دسترس‌پذیری و سازگاری

- [x] **E18 — کیبورد:** ناوبرها، تب‌ها، منوها، حالت‌ها و جداکننده‌ها بدون ماوس قابل استفاده باشند؛ پنل بسته کنترل focusable باقی نگذارد؛ modal و پنل موقت focus را برگردانند.
- [x] **E19 — فارسی و متن مختلط:** رابط فارسی RTL و مسیر/کد LTR مناسب داشته باشد؛ جهت متن از جهت زبان رابط مستقل باشد؛ انتخاب، cursor، لینک و فایل هم‌نام در هر دو زبان آزمایش شود.
- [x] **E20 — اندازهٔ کوچک و بزرگ:** در عرض‌های ۳۶۰، ۷۶۸، ۱۰۲۴ و ۱۴۴۰، متن و کنترل خروج از پنل‌ها قابل دسترس بمانند؛ صفحه scroll افقی ناخواسته نگیرد؛ بازشدن هم‌زمان ابزارها، بوم را به نوار باریک تبدیل نکند.
- [x] **E21 — تم و حرکت:** light/dark کنتراست متن و focus کافی داشته باشند؛ reduced motion رعایت شود؛ tooltip تنها راه تشخیص کنترل حیاتی نباشد.
- [x] **E22 — اطلاعات وضعیت مفید:** وضعیت ذخیره، تعداد کلمه و مکان متن قابل مشاهده باشد؛ پیام بازیابی یا موتور جای دستور اصلی نوشتن را اشغال نکند؛ خطا قابل اقدام باشد.

## سناریوهای راستی‌آزمایی

آزمون خودکار باید در CodeMirror واقعی تایپ کند؛ پرکردن textarea پنهان فقط برای مشاهدهٔ مقدار، شواهد تجربهٔ ادیتور نیست. `scripts/audit_desktop_documents.py` پایهٔ مناسبی برای استقلال undo، caret/scroll، metadata و رقابت آماده‌سازی سند است. `scripts/audit_desktop_design.py` برای تصویر و هندسه، و `scripts/audit_desktop_ui.py` برای modal، فرمان‌ها و امنیت پیش‌نمایش قابل گسترش‌اند. آزمون‌های سورس و Node مکمل این سناریوها هستند.

| سناریو | شواهد مورد انتظار |
| --- | --- |
| فایل عادی → نوشتن → سند دوم → برگشت → Undo/Redo | متن، history، caret و scroll مستقل؛ اسناد باز در Explorer؛ dirty درست. |
| Write → Source → Reading → Split → Write | نقش هر نما، نبود تغییر پنهانی در Reading، پیش‌نمایش سند درست، حفظ متن و history. |
| Explorer و outline هم‌زمان → جمع‌کردن یکی → Focus → خروج | استقلال پنل‌ها، reclaim فضای متن، focus درست و بازیابی چیدمان. |
| Quick Open → فیلتر نام فارسی/انگلیسی → Enter → Escape در نوبت بعد | فایل صحیح، مسیر تشخیص‌پذیر، Arrow navigation و برگشت focus. |
| انتخاب متن → قالب‌بندی → Undo → Find/Replace | اجرا در selection درست، history قابل پیش‌بینی، Find سازگار با حالت نمایش. |
| سند بلند و مختلط در چهار ترکیب زبان/تم و چهار عرض | outline و cursor درست، بدون overflow و کنترل گمشده؛ تصویر بازبینی‌شده. |
| آماده‌سازی تصویر کند + تایپ در سند قابل دیدن | تغییر متعلق به همان فایل روی صفحه؛ نتیجهٔ دیررس لغوشده انتخاب را نرباید. |
| metadata ساختاریافته + Export + برگشت به متن | YAML دست‌نخورده، عملیات روی سند صحیح، برگشت به موقعیت قبلی نوشتن. |

شواهد اجرای هر مورد و محدودیت باقی‌مانده باید پس از پیاده‌سازی ثبت شود. عکس زیباتر به‌تنهایی پذیرش این بازطراحی نیست؛ سناریوهای بالا مشخص می‌کنند آیا کار با فایل و متن واقعاً بهتر شده است.

## وضعیت اجرای معیارها

معیارهای E01 تا E22 با پیاده‌سازی و آزمون‌های این مرحله بسته شدند. شواهد، حدود آزمون و موارد باقی‌مانده در [گزارش نتیجهٔ بازطراحی](EDITOR_UX_RESULTS.fa.md) ثبت شده‌اند. E23 تا E25 برنامهٔ توسعهٔ بعدی‌اند و انجام‌شده اعلام نمی‌شوند.
