# نتیجهٔ بازطراحی محیط Markdown

تاریخ تکمیل بررسی: ۲۰۲۶-۱۰-۱۲. مبنای مقایسه: `b49855d`.

پژوهش، مشکلات نسخهٔ قبلی و معیارهای پذیرش در [بررسی تجربهٔ ادیتور](EDITOR_UX_REVIEW.fa.md) ثبت شده‌اند. طراحی جدید، جریان فایل مستقل و نوشتن را در مرکز محیط دسکتاپ قرار می‌دهد.

## تغییرهای قابل استفاده

- ناوبر فایل‌ها برای تمام سندهای باز، بدون الزام ساخت پروژه؛ نام، مسیر، سند فعال و وضعیت ذخیره روشن‌اند. ساختار و مشخصات سند در پنلی مستقل قرار دارند.
- انتخاب فایل با `Ctrl/Cmd+P`، فرمان با `Ctrl/Cmd+Shift+P` و عنوان با `Ctrl/Cmd+Shift+O` مسیرهای جدا دارند. قالب‌بندی، درج بلوک و عنوان‌های مختلف نیز در فرمان‌ها جست‌وجوشدنی‌اند.
- چهار نمای مشخص: نوشتن با قالب‌بندی در همان متن، سورس واقعی، خواندن غیرقابل ویرایش، و مقایسهٔ سورس با نتیجه. پیش‌نمایش محتوا با صفحه‌بندی PDF یکی معرفی نمی‌شود.
- بوم نوشتن با ستون ۷۶۰ پیکسلی پیش‌فرض و گزینهٔ عریض؛ نوار قالب‌بندی اختیاری است. درج و جست‌وجو همیشه مسیر مشخص دارند؛ انتخاب متن ابزار کوچک قالب‌بندی نشان می‌دهد و `/` در ابتدای خط، بلوک Markdown درج می‌کند.
- حالت تمرکز ابزارهای اضافی را از نمایش و دسترسی با Tab خارج می‌کند. خروج با کنترل قابل مشاهده و Escape انجام می‌شود؛ چیدمان قبلی برمی‌گردد.
- در پنجرهٔ کوچک، پنل‌ها مستقل و قابل بستن‌اند؛ حالت مقایسه عمودی می‌شود. در اندازهٔ ۱۴۴۰×۹۰۰، بوم ویرایش پیش‌فرض ۷۴۸ پیکسل ارتفاع دارد، حدود ۸۳٫۱٪ پنجره.

## حفاظت از جریان کار

تغییر نما و جابه‌جایی سند، متن، history، انتخاب و محل پیمایش هر سند را حفظ می‌کند. انتخاب سریع عنوان به شناسه و نسخهٔ سند مربوط است؛ نتیجهٔ قدیمی اجازه ندارد کاربر را در سند جدید به خط نامرتبط ببرد.

خواندن یک مقالهٔ مستقل و غیرقابل ویرایش است. قالب‌بندی، جایگزینی، history و checkboxهای رندرشده نمی‌توانند بافر پنهان را تغییر دهند. جست‌وجو/جایگزینی از Reading، نمای سورس قابل مشاهده را باز می‌کند. محتوای قدیمی هنگام انتظار برای رندر جدید به‌عنوان نتیجهٔ تازه نمایش داده نمی‌شود؛ بارگذاری سند خالی هم نشانگر معلق باقی نمی‌گذارد. IDها، ارجاع‌های SVG، ARIA و پانویس‌های خواندن از پنل مقایسه جدا هستند.

چسباندن ناهم‌زمان به سند، نسخهٔ متن، قصد فعال‌سازی و انتخاب اولیه وابسته است. عوض‌شدن سند یا محل نوشتن، چسباندن دیررس را کنار می‌گذارد. خروجی پس از ذخیرهٔ دیرهنگام نیز نمی‌تواند انتخاب جدید را کنار بزند یا نسخهٔ قدیمی متن را صادر کند. بازگشت از خروجی، همان سند و نمای خواندن/نوشتن را حفظ می‌کند. پیش‌نمایش کامل کتاب در پنل قابل مشاهده قرار می‌گیرد و پیش‌نمایش خودکار سند بلافاصله جای آن را نمی‌گیرد.

در نوشتن معمولی، DOM کامل مقالهٔ خواندن بازسازی نمی‌شود. تایپ نیز باعث بازسازی فهرست تمام فایل‌های پروژه نمی‌شود. اصلاح‌ها از ساخت دوبارهٔ بافر برای تغییر تنظیمات نمایشی استفاده نمی‌کنند.

## حدود این مرحله

آزمون مرورگر، CodeMirror واقعی را اجرا و در آن تایپ می‌کند؛ bridge بومی و پاسخ‌های موتور برای رقابت درخواست‌ها و حالت‌های خطا fixture کنترل‌شده‌اند. این شواهد جای آزمون نصب‌کننده و WebView واقعی هر سیستم‌عامل یا مشاهدهٔ کاربران واقعی را نمی‌گیرد.

پوشهٔ عادی بدون manifest، هم‌سطح‌کردن Browser Studio با قابلیت‌های ادیتور دسکتاپ و پژوهش با کاربران واقعی، موارد E23 تا E25 در برنامهٔ بعدی‌اند. این مرحله جریان کامل فایل‌های مستقل و بازطراحی ادیتور دسکتاپ را تحویل می‌دهد. fallback مبتنی بر textarea همچنان قابلیت‌های کمتری از CodeMirror دارد.

خطوط سورسِ بلوک کد و جدول، جهت ثابتِ مربوط به همان بلوک دارند؛ fence بسته و separator جدول دیگر از جهت رابط تبعیت نمی‌کنند. متن فارسی و انگلیسی بیرون این بلوک‌ها جهت طبیعی خود را حفظ می‌کند. در ابزار انتخاب متن نیز فوکوس تأخیری نمی‌تواند پس از حرکت با فلش، کاربر را به دکمهٔ اول برگرداند.

| بررسی | نتیجه و محل شواهد |
| --- | --- |
| Node | ۲۵۵ آزمون موفق؛ `npm --prefix apps/desktop test` |
| Python دسکتاپ | ۴۱ آزمون موفق، بدون skip؛ `tests/test_desktop_app.py` با Node در PATH |
| UX جدید | ۲۰ سناریو: چهار ترکیب زبان/تم، هرکدام ۲۱ بررسی، و ۱۶ حالت اندازه/زبان/تم؛ `build/editor-ux-final-pane-check/report.json` |
| مالکیت سند | چهار ترکیب زبان/تم و یک سناریوی scope تأخیری؛ undo/caret/scroll و race بازکردن فایل موفق |
| UI و امنیت محتوا | ۴۳ بررسی موفق، شامل dialog، رفتار صفحه‌کلید، حالت‌ها و پاک‌سازی پیش‌نمایش |
| چیدمان و کنتراست | ۴۰ حالت دسترسی به کنترل‌ها موفق؛ نقضی در نقاط کنتراست بررسی‌شده گزارش نشد |
| corpus Markdown | چهار اجرای Write/Source/Split موفق؛ هرکدام ۹ رفتار واقعی تایپ؛ Write همچنین پنج بررسی آشکارشدن سورس |
| جهت و نشانگر سورس | ۲۸ حالت موفق؛ جهت بلوک، حرکت Home/فلش، مختصات نشانگر و offset واقعی UTF-16، متن دقیق و undo/redo |
| تصویر | ۴۰ تصویر تازه در `build/editor-ux-final-design/`؛ نمونه‌های Write، Read، Source فارسی و پنجرهٔ کوچک بازبینی شدند |
| بستهٔ frontend | ساخت و integrity موفق؛ bundle ادیتور بازتولید و checksum آن تأیید شد |

اسکریپت‌های `audit_desktop_editor_ux.py`، `audit_desktop_documents.py`، `audit_desktop_ui.py`، `audit_desktop_design.py`، `audit_editor_markdown.py` و `audit_editor_source_direction.py` شواهد مرورگر را بازتولید می‌کنند. در gate corpus، نبود decoration مورد انتظار، خطای مرورگر، رفتار ناموفق تایپ یا نمای نادرست، exit ناموفق می‌دهد؛ گزارش چاپ‌شده به‌تنهایی موفقیت محسوب نمی‌شود.

تغییرهای نسخهٔ برنامه و راهنما که از قبل در workspace بودند، در کامیت‌های بازطراحی وارد نشده‌اند. کامیت‌ها با `mragetsars <mragetsars@gmail.com>` و قالب پیام‌های قبلی ثبت شدند؛ این مرحله انتشار release یا push نیست.
